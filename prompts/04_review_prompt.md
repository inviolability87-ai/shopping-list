# 4단계 프롬프트 — PRD 부합 검토 및 버그 점검

완성된 `app.py`, `requirements.txt`를 `PRD.md` 기준으로 자세히 검토해줘. 실제 코드 수정은 하지 말고, 검토 결과만 보고해줘.

## 검토 항목

### 1. 기능 요구사항 충족 여부 (PRD 4번 항목 기준)
- [ ] F1 아이템 추가: 빈 값 입력, 중복 아이템, 공백만 입력 등 예외 케이스에서도 의도대로 동작하는가?
- [ ] F2 아이템 삭제: 여러 아이템이 있을 때 삭제 대상이 정확히 일치하는가? (인덱스/키 꼬임 없는지)
- [ ] F3 아이템 수정: 수정 중 다른 아이템을 조작하거나 페이지가 rerun 될 때 상태가 꼬이지 않는가?
- [ ] F4 아이템 체크: 체크 상태가 다른 조작(추가/삭제/수정) 이후에도 올바르게 유지되는가?
- [ ] F5 세션 상태 유지: 여러 위젯이 같은 key를 사용해 충돌하지 않는가?

### 2. 성공 기준 검증 (PRD 8번 항목 기준)
- [ ] 추가 시 즉시 리스트 반영
- [ ] 삭제 시 즉시 리스트 제거
- [ ] 수정 시 변경 내용 즉시 반영
- [ ] 체크 시 시각적 구분 표시

### 3. 코드 품질 및 버그 점검
- Streamlit의 `st.session_state`와 위젯 key 관리에서 흔히 발생하는 버그(예: 리스트 인덱스 기반 key 사용 시 삭제/재정렬 후 key 충돌) 여부
- 위젯 rerun 타이밍 문제로 인한 상태 불일치 여부
- 예외 상황(빈 리스트에서 삭제 시도, 동시에 여러 버튼 클릭 등) 처리 여부
- 불필요하게 복잡하거나 중복된 코드가 있는지

### 4. 비기능 요구사항 확인 (PRD 5번 항목 기준)
- `app.py` 단일 파일로 실행 가능한가?
- `requirements.txt`에 필요한 의존성이 누락 없이 명시되어 있는가?
- `streamlit run app.py` 명령으로 별도 설정 없이 바로 실행되는가?

## 출력 형식
검토 결과를 다음 형식으로 정리해줘.

1. **PRD 충족 여부 요약** (충족/미충족 항목 리스트)
2. **발견된 버그/이슈** (파일명:라인 번호와 함께, 재현 시나리오 포함)
3. **개선 권장 사항** (버그는 아니지만 개선하면 좋은 부분, 우선순위 낮음)

버그가 없다면 "발견된 버그 없음"이라고 명시하고, 확인한 시나리오를 간단히 나열해줘.
